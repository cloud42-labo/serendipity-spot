## 1. この製品は何か

**行ってみたいが、そこ自体は目的地ではない場所**を留めておき、別の用事でたまたま
近くに来たときに知らせるアプリ。

目的地なら自分で行く。予定を立て、経路を調べ、時間を取る。通知は要らない。

問題は「行ってみたいが、そのためだけに出かけるほどではない」場所である。この種の場所は
行きたい気持ちがあっても、わざわざ行く理由が足りない。結果として、一生行かない。

このアプリは、その場所を**あなたが近くに来た瞬間に思い出させる**。行く理由を作るのではなく、
既にそこにいるという事実を使う。

## 2. 解こうとしている問題

### 2.1 「行きたい場所リスト」は読み返されない

メモアプリ、ブックマーク、地図アプリの保存リスト。どれも溜まる一方で、見返す習慣がない。
見返さなければ存在しないのと同じである。

### 2.2 思い出すタイミングが行動と噛み合わない

家でリストを眺めても、その場所は遠い。近くにいるときに限って、思い出さない。
**情報を持っていること**と**必要な瞬間にそれが出てくること**は別の問題である。

### 2.3 既存の地図アプリでは解けない

地図アプリの「保存済み」は、自分から開かないと出てこない。リストが増えるほど埋もれる。
近接通知の仕組みを持つものもあるが、目的地設定や経路案内と結びついており、
「目的地ではない場所」を扱う設計にはなっていない。

## 3. 解決の形

1. 気になった場所を地図上にピンで留める（検索でも、地図タップでも、中央の照準でも）
2. **忘れてよい。** リストを見返す必要はない
3. その場所の半径150m以内に外から入ると、アプリを閉じていても通知が届く
4. 通知をタップすると、**現在地からそこまでの徒歩ルートと距離・所要時間**が出る
5. 寄るかどうかはその場で決める。寄らなくてもよい

「ついで」であることが本質なので、寄れなかったことへの罪悪感が発生しない設計にしている。
達成率も、連続記録も、リマインダーの再送もない。

**4 は v1.0.0 で加えた。** 「近くにいる」と知らされても、それが徒歩3分なのか20分なのかで
判断は変わる。知らせるだけでは決められない、という実利用からの反映である。

## 4. スコープ

### やること

| 機能 | 内容 |
| :--- | :--- |
| スポットの登録 | 地図タップ／住所・駅名・施設名の検索／「＋」で地図中央 |
| 一覧・編集・削除 | 画面下部から引き出す一覧で操作する |
| 近接通知 | 半径150m以内に**外から入った**ときに通知＋バイブ |
| 再通知の抑制 | 同じスポットは3時間空けないと再通知しない |
| 徒歩ルート表示 | 通知タップで、現在地からの経路・距離・所要時間を地図に描く |
| ストリートビュー | ピンの地点の様子をアプリ内で確認する |
| データの保管 | 利用者自身のGoogleドライブ上のスプレッドシート |
| 診断 | バージョン・ジオフェンス登録数・最終受信時刻・テスト通知 |

### やらないこと

- **ターンバイターンの経路案内**。徒歩ルートは「寄るか決める材料」として距離と時間を
  出すところまで。案内そのものは地図アプリの仕事であり、必要ならそちらへ渡す
- **レビュー・評価・おすすめ**。他人の評価は「ついで」の判断材料ではない
- **共有・SNS的な機能**。個人の覚え書きとして閉じる
- **達成の記録や催促**。寄らなかったことを咎める仕組みを持たない
- **Play ストアでの配布**。家族・友人に配る規模では URL 配布で足りる

## 5. データの扱い

スポットは**利用者自身のGoogleドライブ上のスプレッドシート**に保存される。
運営側のサーバーは存在しない。

- 利用者はスプレッドシートを直接開いて閲覧・編集・書き出しができる
- アプリを消してもデータは残る。入れ直せば同じシートを読みに行く
- **要求する権限は `drive.file` の1つだけ。** このアプリが作ったファイル以外は見えない
- 位置情報は端末内でのみ使われ、外部に送信されない

「自分のデータが自分の手元にある」ことを、説明ではなく構造で担保している。

v1.0.0 では、以前要求していた `spreadsheets` スコープを**外した**。使っている
Sheets API のメソッドはすべて `drive.file` で通るため、そもそも不要だった。
結果として、利用者に出ていた「このアプリは Google で確認されていません」の警告が消えた。

## 6. 制約と前提

- **Android 8.0 以降**が必要（Google Play 開発者サービスを含む端末）
- 位置情報の権限を「**常に許可**」にする必要がある。「使用中のみ」では、アプリを
  閉じている間の通知が仕組み上届かない
- **通知できるスポットは100件まで**（Android のジオフェンス制限）。101件目以降も登録・
  一覧はできるが、古い方から通知の対象外になる。画面に「（N / 100）」として常時表示する
- 通知は即座ではなく、数十秒〜数分の遅れがある（省電力のため OS が位置情報をまとめて処理する）
- 端末がサイレントモードだと音が鳴らない（端末側の設定で個別に許可できる）
- 配布は GitHub Releases の固定URLから。Play ストアには出していない

**利用者側の Google Cloud 設定は不要になった。** v0.8.0 時点の制約はここで解消している。

## 7. 成功をどう見るか

**通知をきっかけに実際に寄った回数。** 登録数でも起動回数でもない。

登録だけ増えて一度も寄らないなら、それは「行きたい場所リスト」に戻っただけであり、
このアプリは問題を解いていない。

## 8. 現状と次の段階

v1.0.0 は**正式リリース**である。作者以外のアカウントで、作者の Google Cloud 設定を
何も触らずに、インストールからスポット登録まで通ることを確認した上で出している。

**v0.8.0 の時点で「一般配布に必要」と書いていた3項目のうち、2つは解消し、1つは取り下げた。**

| v0.8.0 で挙げた条件 | v1.0.0 での結論 |
| :--- | :--- |
| OAuth同意画面の審査 | **不要になった。** 機密スコープ `spreadsheets` を外したため、審査も100人上限も対象外 |
| 利用者側の Google Cloud 設定を不要にする | **解消。** URLからAPKを入れ、Googleでログインするだけ |
| Play ストアでの配布 | **取り下げ。** 家族・友人という規模に対して手続きが重い |

### この先に考えていること

- 通知が来た場所に実際に寄れたかを、負担なく残せる形があるか（達成率にはしない）
- 複数端末で使うときの挙動の確認
- iOS 版の可否（現時点で予定なし）

いずれも利用者からの要望が出てから着手する。**使われていない機能を先に作らない。**
