# Google Play バックグラウンド位置情報 申告ガイド

対象: `SPOT-06-S01-T01`

## 利用目的

「ついでにスポット」は、利用者が登録したスポットへの接近を検知して通知するためにバックグラウンド位置情報を利用する。

- アプリを閉じているとき／利用していないときにも位置情報を利用する。
- 利用目的は、登録スポットへの接近をジオフェンスで検知して通知すること。
- ジオフェンスの近接判定は端末上で行う。
- 近接判定のための位置情報を開発者サーバーへ送信しない。
- 徒歩ルート表示を利用者が明示的に操作した場合のみ、その時点の現在地とスポット座標を Google Directions API へ送信する。これはバックグラウンドの継続送信ではない。

## アプリ内 prominent disclosure

OSの位置情報権限ダイアログより前に、初回オンボーディング画面で以下の内容を表示する。

> 登録したスポットへの接近を検知して通知するため、アプリを閉じているときや使用していないときにも位置情報を利用します。近接判定は端末上で行われ、この判定のための位置情報が開発者へ送信されることはありません。
>
> 次に、位置情報（バックグラウンド利用を含む）と通知の許可を確認します。許可しない場合、近づいたときの通知は利用できません。

実装: `android/app/src/main/java/com/cloud42labo/serendipityspot/ui/OnboardingIntro.kt`

## Play Console「位置情報の権限」申告文（下書き）

### なぜバックグラウンド位置情報が必要か

利用者が「行ってみたいが、それ自体を目的地にはしない場所」を登録しておき、別の用事で偶然その場所の近くへ来たときに通知することが本アプリの中核機能です。この通知は、アプリを画面に表示していない時間にも登録スポットへの接近を検知する必要があるため、バックグラウンド位置情報が必要です。

### バックグラウンド位置情報を使う機能

登録スポットの半径150mへの進入を Android Geofencing API で検知し、接近通知を表示します。利用者がこの機能を利用しない場合、バックグラウンド位置情報を許可する必要はありませんが、接近通知は動作しません。

### データの扱い

ジオフェンスによる接近判定は端末上で行い、この判定のための現在地を開発者へ送信・保存しません。登録スポットの座標は利用者自身の Google Drive 上のスプレッドシートに保存されます。徒歩ルート表示を利用者が明示的に選択した場合だけ、その時点の現在地とスポット座標を Google Directions API に送信します。

## デモ動画 撮影チェックリスト

Play Consoleでバックグラウンド位置情報のデモ動画を求められた場合は、次の一連の操作を1本の動画で示す。

1. アプリを新規インストールまたはアプリデータを消去した状態から起動する。
2. 初回オンボーディングの prominent disclosure を全文読める状態で表示する。
3. 「はじめる」を押し、OSの位置情報権限画面へ進む。
4. バックグラウンド利用に必要な権限（「常に許可」相当）を有効化する流れを示す。
5. スポットを登録する。
6. アプリを閉じる、またはバックグラウンドへ移す。
7. 登録スポットへ外側から接近し、接近通知が表示されることを示す。
8. 可能であれば通知をタップし、登録スポットがアプリ上で開くところまで示す。

動画内では「権限を求める理由」「バックグラウンドで使われる機能」「ユーザーに見える効果」が同じ流れで分かるようにする。

## Data Safetyとの整合

- 正確な位置情報: アプリ機能のために利用。
- ジオフェンス近接判定: 端末上で処理し、開発者へ送信しない。
- 徒歩ルート: 利用者が明示操作した場合のみ Google Directions API へ現在地と目的地座標を送信。
- 広告・分析目的で位置情報を利用しない。
- プライバシーポリシーの「位置情報」節と同じ説明に揃える。
